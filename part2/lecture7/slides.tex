\section{快速开始}

\begin{frame}[t]{快速开始}

下面的一段HTML代码将作为例子被多次用到.这是 爱丽丝梦游仙境的 的一段内容(以后内容中简称为 爱丽丝 的文档):

\end{frame}

html_doc = """
<html><head><title>The Dormouse's story</title></head>
<body>
<p class="title"><b>The Dormouse's story</b></p>

\section{如何使用}

\begin{frame}[t]{如何使用}

将一段文档传入BeautifulSoup 的构造方法,就能得到一个文档的对象, 可以传入一段字符串或一个文件句柄.

\end{frame}


\begin{frame}[t,fragile]{如何使用}


\begin{verbatim}

from bs4 import BeautifulSoup

soup = BeautifulSoup(open("index.html"))

soup = BeautifulSoup("<html>data</html>")


\end{verbatim}


\end{frame}


\begin{frame}[t]{如何使用}

首先,文档被转换成Unicode,并且HTML的实例都被转换成Unicode编码

\end{frame}


\begin{frame}[t,fragile]{如何使用}


\begin{verbatim}

BeautifulSoup("Sacr&eacute; bleu!")
<html><head></head><body>Sacré bleu!</body></html>

\end{verbatim}


\end{frame}


\begin{frame}[t]{如何使用}

然后,Beautiful Soup选择最合适的解析器来解析这段文档,如果手动指定解析器那么Beautiful Soup会选择指定的解析器来解析文档.(参考 解析成XML ).

\end{frame}

\section{对象的种类}

\begin{frame}[t]{对象的种类}

Beautiful Soup将复杂HTML文档转换成一个复杂的树形结构,每个节点都是Python对象,所有对象可以归纳为4种: Tag , NavigableString , BeautifulSoup , Comment .

\end{frame}


\begin{frame}[t]{对象的种类}

Tag 对象与XML或HTML原生文档中的tag相同:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

soup = BeautifulSoup('<b class="boldest">Extremely bold</b>')
tag = soup.b
type(tag)
# <class 'bs4.element.Tag'>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

Tag有很多方法和属性,在 遍历文档树 和 搜索文档树 中有详细解释.现在介绍一下tag中最重要的属性: name和attributes

\end{frame}


\begin{frame}[t]{对象的种类}

每个tag都有自己的名字,通过 .name 来获取:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag.name
# u'b'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

如果改变了tag的name,那将影响所有通过当前Beautiful Soup对象生成的HTML文档:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag.name = "blockquote"
tag
# <blockquote class="boldest">Extremely bold</blockquote>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

一个tag可能有很多个属性. tag <b class="boldest"> 有一个 “class” 的属性,值为 “boldest” . tag的属性的操作方法与字典相同:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag['class']
# u'boldest'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

也可以直接”点”取属性, 比如: .attrs :

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag.attrs
# {u'class': u'boldest'}


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

tag的属性可以被添加,删除或修改. 再说一次, tag的属性操作方法与字典一样

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag['class'] = 'verybold'
tag['id'] = 1
tag
# <blockquote class="verybold" id="1">Extremely bold</blockquote>

del tag['class']
del tag['id']
tag
# <blockquote>Extremely bold</blockquote>

tag['class']
# KeyError: 'class'
print(tag.get('class'))
# None


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

HTML 4定义了一系列可以包含多个值的属性.在HTML5中移除了一些,却增加更多.最常见的多值的属性是 class (一个tag可以有多个CSS的class). 还有一些属性 rel , rev , accept-charset , headers , accesskey . 在Beautiful Soup中多值属性的返回类型是list:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

css_soup = BeautifulSoup('<p class="body strikeout"></p>')
css_soup.p['class']
# ["body", "strikeout"]

css_soup = BeautifulSoup('<p class="body"></p>')
css_soup.p['class']
# ["body"]


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

如果某个属性看起来好像有多个值,但在任何版本的HTML定义中都没有被定义为多值属性,那么Beautiful Soup会将这个属性作为字符串返回

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

id_soup = BeautifulSoup('<p id="my id"></p>')
id_soup.p['id']
# 'my id'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

将tag转换成字符串时,多值属性会合并为一个值

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

rel_soup = BeautifulSoup('<p>Back to the <a rel="index">homepage</a></p>')
rel_soup.a['rel']
# ['index']
rel_soup.a['rel'] = ['index', 'contents']
print(rel_soup.p)
# <p>Back to the <a rel="index contents">homepage</a></p>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

如果转换的文档是XML格式,那么tag中不包含多值属性

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

xml_soup = BeautifulSoup('<p class="body strikeout"></p>', 'xml')
xml_soup.p['class']
# u'body strikeout'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

字符串常被包含在tag内.Beautiful Soup用 NavigableString 类来包装tag中的字符串:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag.string
# u'Extremely bold'
type(tag.string)
# <class 'bs4.element.NavigableString'>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

一个 NavigableString 字符串与Python中的Unicode字符串相同,并且还支持包含在 遍历文档树 和 搜索文档树 中的一些特性. 通过 unicode() 方法可以直接将 NavigableString 对象转换成Unicode字符串:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

unicode_string = unicode(tag.string)
unicode_string
# u'Extremely bold'
type(unicode_string)
# <type 'unicode'>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

tag中包含的字符串不能编辑,但是可以被替换成其它的字符串,用 replace\_with() 方法:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

tag.string.replace_with("No longer bold")
tag
# <blockquote>No longer bold</blockquote>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

NavigableString 对象支持 遍历文档树 和 搜索文档树 中定义的大部分属性, 并非全部.尤其是,一个字符串不能包含其它内容(tag能够包含字符串或是其它tag),字符串不支持 .contents 或 .string 属性或 find() 方法.

\end{frame}


\begin{frame}[t]{对象的种类}

如果想在Beautiful Soup之外使用 NavigableString 对象,需要调用 unicode() 方法,将该对象转换成普通的Unicode字符串,否则就算Beautiful Soup已方法已经执行结束,该对象的输出也会带有对象的引用地址.这样会浪费内存.

\end{frame}


\begin{frame}[t]{对象的种类}

BeautifulSoup 对象表示的是一个文档的全部内容.大部分时候,可以把它当作 Tag 对象,它支持 遍历文档树 和 搜索文档树 中描述的大部分的方法.

\end{frame}


\begin{frame}[t]{对象的种类}

因为 BeautifulSoup 对象并不是真正的HTML或XML的tag,所以它没有name和attribute属性.但有时查看它的 .name 属性是很方便的,所以 BeautifulSoup 对象包含了一个值为 “[document]” 的特殊属性 .name

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

soup.name
# u'[document]'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

Tag , NavigableString , BeautifulSoup 几乎覆盖了html和xml中的所有内容,但是还有一些特殊对象.容易让人担心的内容是文档的注释部分:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

markup = "<b><!--Hey, buddy. Want to buy a used parser?--></b>"
soup = BeautifulSoup(markup)
comment = soup.b.string
type(comment)
# <class 'bs4.element.Comment'>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

Comment 对象是一个特殊类型的 NavigableString 对象:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

comment
# u'Hey, buddy. Want to buy a used parser'


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

但是当它出现在HTML文档中时, Comment 对象会使用特殊的格式输出:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

print(soup.b.prettify())
# <b>
#  <!--Hey, buddy. Want to buy a used parser?-->
# </b>


\end{verbatim}


\end{frame}


\begin{frame}[t]{对象的种类}

Beautiful Soup中定义的其它类型都可能会出现在XML的文档中: CData , ProcessingInstruction , Declaration , Doctype .与 Comment 对象类似,这些类都是 NavigableString 的子类,只是添加了一些额外的方法的字符串独享.下面是用CDATA来替代注释的例子:

\end{frame}


\begin{frame}[t,fragile]{对象的种类}


\begin{verbatim}

from bs4 import CData
cdata = CData("A CDATA block")
comment.replace_with(cdata)

print(soup.b.prettify())
# <b>
#  <![CDATA[A CDATA block]]>
# </b>


\end{verbatim}


\end{frame}

\section{遍历文档树}

\begin{frame}[t]{遍历文档树}

还拿”爱丽丝梦游仙境”的文档来做例子:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

html_doc = """
<html><head><title>The Dormouse's story</title></head>

<p class="title"><b>The Dormouse's story</b></p>

<p class="story">Once upon a time there were three little sisters; and their names were
<a href="http://example.com/elsie" class="sister" id="link1">Elsie</a>,
<a href="http://example.com/lacie" class="sister" id="link2">Lacie</a> and
<a href="http://example.com/tillie" class="sister" id="link3">Tillie</a>;
and they lived at the bottom of a well.</p>

<p class="story">...</p>
"""

from bs4 import BeautifulSoup
soup = BeautifulSoup(html_doc)


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

通过这段例子来演示怎样从文档的一段内容找到另一段内容

\end{frame}


\begin{frame}[t]{遍历文档树}

一个Tag可能包含多个字符串或其它的Tag,这些都是这个Tag的子节点.Beautiful Soup提供了许多操作和遍历子节点的属性.

\end{frame}


\begin{frame}[t]{遍历文档树}

注意: Beautiful Soup中字符串节点不支持这些属性,因为字符串没有子节点

\end{frame}


\begin{frame}[t]{遍历文档树}

操作文档树最简单的方法就是告诉它你想获取的tag的name.如果想获取 <head> 标签,只要用 soup.head :

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

soup.head
# <head><title>The Dormouse's story</title></head>

soup.title
# <title>The Dormouse's story</title>


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

这是个获取tag的小窍门,可以在文档树的tag中多次调用这个方法.下面的代码可以获取<body>标签中的第一个<b>标签:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

soup.body.b
# <b>The Dormouse's story</b>


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

通过点取属性的方式只能获得当前名字的第一个tag:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

soup.a
# <a class="sister" href="http://example.com/elsie" id="link1">Elsie</a>


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

如果想要得到所有的<a>标签,或是通过名字得到比一个tag更多的内容的时候,就需要用到 Searching the tree 中描述的方法,比如: find\_all()

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

soup.find_all('a')
# [<a class="sister" href="http://example.com/elsie" id="link1">Elsie</a>,
#  <a class="sister" href="http://example.com/lacie" id="link2">Lacie</a>,
#  <a class="sister" href="http://example.com/tillie" id="link3">Tillie</a>]


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

tag的 .contents 属性可以将tag的子节点以列表的方式输出:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

head_tag = soup.head
head_tag
# <head><title>The Dormouse's story</title></head>

head_tag.contents
[<title>The Dormouse's story</title>]

title_tag = head_tag.contents[0]
title_tag
# <title>The Dormouse's story</title>
title_tag.contents
# [u'The Dormouse's story']

\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

BeautifulSoup 对象本身一定会包含子节点,也就是说<html>标签也是 BeautifulSoup 对象的子节点:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

len(soup.contents)
# 1
soup.contents[0].name
# u'html'


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

字符串没有 .contents 属性,因为字符串没有子节点:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

text = title_tag.contents[0]
text.contents
# AttributeError: 'NavigableString' object has no attribute 'contents'


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

通过tag的 .children 生成器,可以对tag的子节点进行循环:

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

for child in title_tag.children:
    print(child)
    # The Dormouse's story


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

.contents 和 .children 属性仅包含tag的直接子节点.例如,<head>标签只有一个直接子节点<title>

\end{frame}


\begin{frame}[t,fragile]{遍历文档树}


\begin{verbatim}

head_tag.contents
# [<title>The Dormouse's story</title>]


\end{verbatim}


\end{frame}


\begin{frame}[t]{遍历文档树}

\end{verbatim}


\end{frame}

\end{frame}

\begin{frame}[t]{搜索文档树}

如果没有合适过滤器,那么还可以定义一个方法,方法只接受一个元素参数 [4] ,如果这个方法返回 True 表示当前元素匹配并且被找到,如果不是则反回 False

\end{frame}


\begin{frame}[t]{搜索文档树}

下面方法校验了当前元素,如果包含 class 属性却不包含 id 属性,那么将返回 True:

\begin{frame}[t,fragile]{搜索文档树}

def has_class_but_no_id(tag):
    return tag.has_attr('class') and not tag.has_attr('id')


\end{verbatim}

\begin{frame}[t,fragile]{搜索文档树}

#  <p class="story">...</p>]


\end{verbatim}


\end{frame}


\begin{frame}[t]{搜索文档树}

返回结果中只有<p>标签没有<a>标签,因为<a>标签还定义了”id”,没有返回<html>和<head>,因为<html>和<head>中没有定义”class”属性.

\end{frame}

def surrounded_by_strings(tag):

    print tag.name

# a
# a
# a
# p

\begin{frame}[t]{搜索文档树}

我们已经用了很大篇幅来介绍 find\_all() 和 find() 方法,Beautiful Soup中还有10个用于搜索的API.它们中的五个用的是与 find\_all() 相同的搜索参数,另外5个与 find() 方法的搜索参数类似.区别仅是它们搜索文档的不同部分.

\end{frame}


\begin{frame}[t]{搜索文档树}

记住: find\_all() 和 find() 只搜索当前节点的所有子节点,孙子节点等. find\_parents() 和 find\_parent() 用来搜索当前节点的父辈节点,搜索方法与普通tag的搜索方法相同,搜索文档搜索文档包含的内容. 我们从一个文档中的一个叶子节点开始:

\end{frame}


\begin{frame}[t,fragile]{搜索文档树}


\begin{verbatim}

a_string = soup.find(text="Lacie")
a_string
# u'Lacie'

a_string.find_parents("a")
# [<a class="sister" href="http://example.com/lacie" id="link2">Lacie</a>]

a_string.find_parent("p")
# <p class="story">Once upon a time there were three little sisters; and their names were
#  <a class="sister" href="http://example.com/elsie" id="link1">Elsie</a>,
#  <a class="sister" href="http://example.com/lacie" id="link2">Lacie</a> and
#  <a class="sister" href="http://example.com/tillie" id="link3">Tillie</a>;
#  and they lived at the bottom of a well.</p>

a_string.find_parents("p", class="title")
# []

\end{verbatim}


\end{frame}


\begin{frame}[t]{搜索文档树}

文档中的一个<a>标签是是当前叶子节点的直接父节点,所以可以被找到.还有一个<p>标签,是目标叶子节点的间接父辈节点,所以也可以被找到.包含class值为”title”的<p>标签不是不是目标叶子节点的父辈节点,所以通过 find\_parents() 方法搜索不到.

\end{frame}


\begin{frame}[t]{搜索文档树}

find\_parent() 和 find\_parents() 方法会让人联想到 .parent 和 .parents 属性.它们之间的联系非常紧密.搜索父辈节点的方法实际上就是对 .parents 属性的迭代搜索.

\end{frame}

\end{frame}

\begin{frame}[t]{搜索文档树}

这2个方法通过 .next\_siblings 属性对当tag的所有后面解析 [5] 的兄弟tag节点进行迭代, find\_next\_siblings() 方法返回所有符合条件的后面的兄弟节点, find\_next\_sibling() 只返回符合条件的后面的第一个tag节点.

\end{frame}

#  <a class="sister" href="http://example.com/tillie" id="link3">Tillie</a>]

\section{指定文档解析器}

\begin{frame}[t]{指定文档解析器}

如果仅是想要解析HTML文档,只要用文档创建 BeautifulSoup 对象就可以了.Beautiful Soup会自动选择一个解析器来解析文档.但是还可以通过参数指定使用那种解析器来解析当前文档.

\end{frame}


\begin{frame}[t]{指定文档解析器}

BeautifulSoup 第一个参数应该是要被解析的文档字符串或是文件句柄,第二个参数用来标识怎样解析文档.如果第二个参数为空,那么Beautiful Soup根据当前系统安装的库自动选择解析器,解析器的优先数序: lxml, html5lib, Python标准库.在下面两种条件下解析器优先顺序会变化:

\end{frame}


\begin{frame}[t]{指定文档解析器}

安装解析器 章节介绍了可以使用哪种解析器,以及如何安装.

\end{frame}


\begin{frame}[t]{指定文档解析器}

如果指定的解析器没有安装,Beautiful Soup会自动选择其它方案.目前只有 lxml 解析器支持XML文档的解析,在没有安装lxml库的情况下,创建 beautifulsoup 对象时无论是否指定使用lxml,都无法得到解析后的对象

\end{frame}


\begin{frame}[t]{指定文档解析器}

Beautiful Soup为不同的解析器提供了相同的接口,但解析器本身时有区别的.同一篇文档被不同的解析器解析后可能会生成不同结构的树型文档.区别最大的是HTML解析器和XML解析器,看下面片段被解析成HTML结构:

\end{frame}


\begin{frame}[t,fragile]{指定文档解析器}


\begin{verbatim}

BeautifulSoup("<a><b /></a>")
# <html><head></head><body><a><b></b></a></body></html>


\end{verbatim}


\end{frame}


\begin{frame}[t]{指定文档解析器}

因为空标签<b />不符合HTML标准,所以解析器把它解析成<b></b>

\end{frame}


\begin{frame}[t]{指定文档解析器}

同样的文档使用XML解析如下(解析XML需要安装lxml库).注意,空标签<b />依然被保留,并且文档前添加了XML头,而不是被包含在<html>标签内:

\end{frame}


\begin{frame}[t,fragile]{指定文档解析器}


\begin{verbatim}

BeautifulSoup("<a><b /></a>", "xml")
# <?xml version="1.0" encoding="utf-8"?>
# <a><b/></a>


\end{verbatim}


\end{frame}


\begin{frame}[t]{指定文档解析器}

HTML解析器之间也有区别,如果被解析的HTML文档是标准格式,那么解析器之间没有任何差别,只是解析速度不同,结果都会返回正确的文档树.

\end{frame}


\begin{frame}[t]{指定文档解析器}

但是如果被解析文档不是标准格式,那么不同的解析器返回结果可能不同.下面例子中,使用lxml解析错误格式的文档,结果</p>标签被直接忽略掉了:

\end{frame}


\begin{frame}[t,fragile]{指定文档解析器}


\begin{verbatim}

BeautifulSoup("<a></p>", "lxml")
# <html><body><a></a></body></html>


\end{verbatim}


\end{frame}


\begin{frame}[t]{指定文档解析器}

使用html5lib库解析相同文档会得到不同的结果:

\end{frame}


\begin{frame}[t,fragile]{指定文档解析器}


\begin{verbatim}

BeautifulSoup("<a></p>", "html5lib")
# <html><head></head><body><a><p></p></a></body></html>


\end{verbatim}


\end{frame}


\begin{frame}[t]{指定文档解析器}

html5lib库没有忽略掉</p>标签,而是自动补全了标签,还给文档树添加了<head>标签.

\end{frame}


\begin{frame}[t]{指定文档解析器}

使用pyhton内置库解析结果如下:

\end{frame}


\begin{frame}[t,fragile]{指定文档解析器}


\begin{verbatim}

BeautifulSoup("<a></p>", "html.parser")
# <a></a>


\end{verbatim}


\end{frame}


\begin{frame}[t]{指定文档解析器}

与lxml [7] 库类似的,Python内置库忽略掉了</p>标签,与html5lib库不同的是标准库没有尝试创建符合标准的文档格式或将文档片段包含在<body>标签内,与lxml不同的是标准库甚至连<html>标签都没有尝试去添加.

\end{frame}


\begin{frame}[t]{指定文档解析器}

因为文档片段“<a></p>”是错误格式,所以以上解析方式都能算作”正确”,html5lib库使用的是HTML5的部分标准,所以最接近”正确”.不过所有解析器的结构都能够被认为是”正常”的.

\end{frame}


\begin{frame}[t]{指定文档解析器}

不同的解析器可能影响代码执行结果,如果在分发给别人的代码中使用了 BeautifulSoup ,那么最好注明使用了哪种解析器,以减少不必要的麻烦.

\end{frame}

\section{编码}

\begin{frame}[t]{编码}

任何HTML或XML文档都有自己的编码方式,比如ASCII 或 UTF-8,但是使用Beautiful Soup解析后,文档都被转换成了Unicode:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

markup = "<h1>Sacr\xc3\xa9 bleu!</h1>"
soup = BeautifulSoup(markup)
soup.h1
# <h1>Sacré bleu!</h1>
soup.h1.string
# u'Sacr\xe9 bleu!'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

这不是魔术(但很神奇),Beautiful Soup用了 编码自动检测 子库来识别当前文档编码并转换成Unicode编码. BeautifulSoup 对象的 .original\_encoding 属性记录了自动识别编码的结果:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

soup.original_encoding
'utf-8'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

编码自动检测 功能大部分时候都能猜对编码格式,但有时候也会出错.有时候即使猜测正确,也是在逐个字节的遍历整个文档后才猜对的,这样很慢.如果预先知道文档编码,可以设置编码参数来减少自动检查编码出错的概率并且提高文档解析速度.在创建 BeautifulSoup 对象的时候设置 from\_encoding 参数.

\end{frame}


\begin{frame}[t]{编码}

下面一段文档用了ISO-8859-8编码方式,这段文档太短,结果Beautiful Soup以为文档是用ISO-8859-7编码:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

markup = b"<h1>\xed\xe5\xec\xf9</h1>"
soup = BeautifulSoup(markup)
soup.h1
<h1>νεμω</h1>
soup.original_encoding
'ISO-8859-7'

\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

通过传入 from\_encoding 参数来指定编码方式:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

soup = BeautifulSoup(markup, from_encoding="iso-8859-8")
soup.h1
<h1>םולש</h1>
soup.original_encoding
'iso8859-8'

\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

少数情况下(通常是UTF-8编码的文档中包含了其它编码格式的文件),想获得正确的Unicode编码就不得不将文档中少数特殊编码字符替换成特殊Unicode编码,“REPLACEMENT CHARACTER” (U+FFFD, �) [9] . 如果Beautifu Soup猜测文档编码时作了特殊字符的替换,那么Beautiful Soup会把 UnicodeDammit 或 BeautifulSoup 对象的 .contains\_replacement\_characters 属性标记为 True .这样就可以知道当前文档进行Unicode编码后丢失了一部分特殊内容字符.如果文档中包含�而 .contains\_replacement\_characters 属性是 False ,则表示�就是文档中原来的字符,不是转码失败.

\end{frame}


\begin{frame}[t]{编码}

通过Beautiful Soup输出文档时,不管输入文档是什么编码方式,输出编码均为UTF-8编码,下面例子输入文档是Latin-1编码:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

markup = b'''
<html>
  <head>
    <meta content="text/html; charset=ISO-Latin-1" http-equiv="Content-type" />
  </head>
  <body>
    <p>Sacr\xe9 bleu!</p>
  </body>
</html>
'''

soup = BeautifulSoup(markup)
print(soup.prettify())
# <html>
#  <head>
#   <meta content="text/html; charset=utf-8" http-equiv="Content-type" />
#  </head>
#  <body>
#   <p>
#    Sacré bleu!
#   </p>
#  </body>
# </html>


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

注意,输出文档中的<meta>标签的编码设置已经修改成了与输出编码一致的UTF-8.

\end{frame}


\begin{frame}[t]{编码}

如果不想用UTF-8编码输出,可以将编码方式传入 prettify() 方法:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

print(soup.prettify("latin-1"))
# <html>
#  <head>
#   <meta content="text/html; charset=latin-1" http-equiv="Content-type" />
# ...


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

还可以调用 BeautifulSoup 对象或任意节点的 encode() 方法,就像Python的字符串调用 encode() 方法一样:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

soup.p.encode("latin-1")
# '<p>Sacr\xe9 bleu!</p>'

soup.p.encode("utf-8")
# '<p>Sacr\xc3\xa9 bleu!</p>'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

如果文档中包含当前编码不支持的字符,那么这些字符将呗转换成一系列XML特殊字符引用,下面例子中包含了Unicode编码字符SNOWMAN:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

markup = u"<b>\N{SNOWMAN}</b>"
snowman_soup = BeautifulSoup(markup)
tag = snowman_soup.b


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

SNOWMAN字符在UTF-8编码中可以正常显示(看上去像是☃),但有些编码不支持SNOWMAN字符,比如ISO-Latin-1或ASCII,那么在这些编码中SNOWMAN字符会被转换成“\&\#9731”:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

print(tag.encode("utf-8"))
# <b>☃</b>

print tag.encode("latin-1")
# <b>&#9731;</b>

print tag.encode("ascii")
# <b>&#9731;</b>


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

编码自动检测 功能可以在Beautiful Soup以外使用,检测某段未知编码时,可以使用这个方法:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

from bs4 import UnicodeDammit
dammit = UnicodeDammit("Sacr\xc3\xa9 bleu!")
print(dammit.unicode_markup)
# Sacré bleu!
dammit.original_encoding
# 'utf-8'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

如果Python中安装了 chardet 或 cchardet 那么编码检测功能的准确率将大大提高.输入的字符越多,检测结果越精确,如果事先猜测到一些可能编码,那么可以将猜测的编码作为参数,这样将优先检测这些编码:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

dammit = UnicodeDammit("Sacr\xe9 bleu!", ["latin-1", "iso-8859-1"])
print(dammit.unicode_markup)
# Sacré bleu!
dammit.original_encoding
# 'latin-1'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

编码自动检测 功能中有2项功能是Beautiful Soup库中用不到的

\end{frame}


\begin{frame}[t]{编码}

使用Unicode时,Beautiful Soup还会智能的把引号 [10] 转换成HTML或XML中的特殊字符:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

markup = b"<p>I just \x93love\x94 Microsoft Word\x92s smart quotes</p>"

UnicodeDammit(markup, ["windows-1252"], smart_quotes_to="html").unicode_markup
# u'<p>I just &ldquo;love&rdquo; Microsoft Word&rsquo;s smart quotes</p>'

UnicodeDammit(markup, ["windows-1252"], smart_quotes_to="xml").unicode_markup
# u'<p>I just &#x201C;love&#x201D; Microsoft Word&#x2019;s smart quotes</p>'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

也可以把引号转换为ASCII码:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

UnicodeDammit(markup, ["windows-1252"], smart_quotes_to="ascii").unicode_markup
# u'<p>I just "love" Microsoft Word\'s smart quotes</p>'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

很有用的功能,但是Beautiful Soup没有使用这种方式.默认情况下,Beautiful Soup把引号转换成Unicode:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

UnicodeDammit(markup, ["windows-1252"]).unicode_markup
# u'<p>I just \u201clove\u201d Microsoft Word\u2019s smart quotes</p>'


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

有时文档的大部分都是用UTF-8,但同时还包含了Windows-1252编码的字符,就像微软的智能引号 [10] 一样.一些包含多个信息的来源网站容易出现这种情况. UnicodeDammit.detwingle() 方法可以把这类文档转换成纯UTF-8编码格式,看个简单的例子:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

snowmen = (u"\N{SNOWMAN}" * 3)
quote = (u"\N{LEFT DOUBLE QUOTATION MARK}I like snowmen!\N{RIGHT DOUBLE QUOTATION MARK}")
doc = snowmen.encode("utf8") + quote.encode("windows_1252")


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

这段文档很杂乱,snowmen是UTF-8编码,引号是Windows-1252编码,直接输出时不能同时显示snowmen和引号,因为它们编码不同:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

print(doc)
# ☃☃☃�I like snowmen!�

print(doc.decode("windows-1252"))
# â˜ƒâ˜ƒâ˜ƒ“I like snowmen!”


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

如果对这段文档用UTF-8解码就会得到 UnicodeDecodeError 异常,如果用Windows-1252解码就回得到一堆乱码.幸好, UnicodeDammit.detwingle() 方法会吧这段字符串转换成UTF-8编码,允许我们同时显示出文档中的snowmen和引号:

\end{frame}


\begin{frame}[t,fragile]{编码}


\begin{verbatim}

new_doc = UnicodeDammit.detwingle(doc)
print(new_doc.decode("utf8"))
# ☃☃☃“I like snowmen!”


\end{verbatim}


\end{frame}


\begin{frame}[t]{编码}

UnicodeDammit.detwingle() 方法只能解码包含在UTF-8编码中的Windows-1252编码内容,但这解决了最常见的一类问题.

\end{frame}


\begin{frame}[t]{编码}

在创建 BeautifulSoup 或 UnicodeDammit 对象前一定要先对文档调用 UnicodeDammit.detwingle() 确保文档的编码方式正确.如果尝试去解析一段包含Windows-1252编码的UTF-8文档,就会得到一堆乱码,比如: â˜ƒâ˜ƒâ˜ƒ“I like snowmen!”.

\end{frame}

\section{解析部分文档}

\begin{frame}[t]{解析部分文档}

如果仅仅因为想要查找文档中的<a>标签而将整片文档进行解析,实在是浪费内存和时间.最快的方法是从一开始就把<a>标签以外的东西都忽略掉. SoupStrainer 类可以定义文档的某段内容,这样搜索文档时就不必先解析整篇文档,只会解析在 SoupStrainer 中定义过的文档. 创建一个 SoupStrainer 对象并作为 parse\_only 参数给 BeautifulSoup 的构造方法即可.

\end{frame}


\begin{frame}[t]{解析部分文档}

SoupStrainer 类接受与典型搜索方法相同的参数：name , attrs , recursive , text , **kwargs 。下面举例说明三种 SoupStrainer 对象：

\end{frame}


\begin{frame}[t,fragile]{解析部分文档}


\begin{verbatim}

from bs4 import SoupStrainer

only_a_tags = SoupStrainer("a")

only_tags_with_id_link2 = SoupStrainer(id="link2")

def is_short_string(string):
    return len(string) < 10

only_short_strings = SoupStrainer(text=is_short_string)


\end{verbatim}


\end{frame}


\begin{frame}[t]{解析部分文档}

再拿“爱丽丝”文档来举例，来看看使用三种 SoupStrainer 对象做参数会有什么不同:

\end{frame}


\begin{frame}[t,fragile]{解析部分文档}


\begin{verbatim}

html_doc = """
<html><head><title>The Dormouse's story</title></head>

<p class="title"><b>The Dormouse's story</b></p>

<p class="story">Once upon a time there were three little sisters; and their names were
<a href="http://example.com/elsie" class="sister" id="link1">Elsie</a>,
<a href="http://example.com/lacie" class="sister" id="link2">Lacie</a> and
<a href="http://example.com/tillie" class="sister" id="link3">Tillie</a>;
and they lived at the bottom of a well.</p>

<p class="story">...</p>
"""

print(BeautifulSoup(html_doc, "html.parser", parse_only=only_a_tags).prettify())
# <a class="sister" href="http://example.com/elsie" id="link1">
#  Elsie
# </a>
# <a class="sister" href="http://example.com/lacie" id="link2">
#  Lacie
# </a>
# <a class="sister" href="http://example.com/tillie" id="link3">
#  Tillie
# </a>

print(BeautifulSoup(html_doc, "html.parser", parse_only=only_tags_with_id_link2).prettify())
# <a class="sister" href="http://example.com/lacie" id="link2">
#  Lacie
# </a>

print(BeautifulSoup(html_doc, "html.parser", parse_only=only_short_strings).prettify())
# Elsie
# ,
# Lacie
# and
# Tillie
# ...
#


\end{verbatim}


\end{frame}
